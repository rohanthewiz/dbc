## What the badge is

`cats/buildbadge` (stdlib only, JS + CSS embedded) shows the short hash of
the commit the binary was built from, `*` for a modified tree. Hovering it
opens a card with BUILD (hash), COMMIT (subject) and WHEN (commit time in
the viewer's zone, with its age). The data comes from three `-ldflags -X`
values (`hash`, `subjectB64`, `when`) set by the package's `stamp.sh`. An
unstamped build falls back to the toolchain's VCS info (hash and time, but
no subject). `Head()` returns `""` when the hash is unknown.

### What differed from gonotes: the CSP

dbc web sends `script-src 'self'` (`web/auth.go securityHeaders`). That
blocked the badge's two inline `<script>`s (the data and the library), so
the placeholder stayed empty. The markup was all there over curl; the new
e2e step caught it in the browser. gonotes sends no CSP.

The fix follows the plan page's existing approach (`explain.ScriptHash`):
allow exactly those scripts by hash.

- `web/pages/buildbadge.go`: `badgeHead = sync.OnceValue(buildbadge.Head)`,
  read by both the page and `BadgeScriptSrc`. `BadgeScriptSrc` regex-extracts
  each inline script body and returns `" 'sha256-…' 'sha256-…'"`, or `""`
  for an unknown build. Using the same cached string guarantees the page and
  the header hash the same bytes.
- `securityHeaders`: `script-src 'self'` + `pages.BadgeScriptSrc()`. Inline
  script in general stays blocked. The plan page sets its own stricter CSP
  and carries no badge.
