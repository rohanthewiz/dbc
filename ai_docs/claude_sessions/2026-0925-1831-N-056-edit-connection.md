# Edit a browser-added connection in place (N-056)

Session: 6ff04c06-ee6c-4793-b05f-80039bced0b0
Date: 2026-09-25

## Ask

Next-list item N-056: edit a connection added in `dbc web` (rename it,
change the DSN or `ai_rows`) instead of removing it and adding it again. That
meant retyping the DSN, since the browser never gets it back. So the edit
form needed a "leave the DSN unchanged" path.

## Changes (`05cd650`)

| Piece | Change |
|---|---|
| `config/config.go` | `ReplaceConn(old, cn)` swaps an entry **in place** (the position is kept, so the sidebar order holds) under `connMu`. It is copy-on-write via `slices.Clone`. A new name another connection holds → `ErrConnExists`. A missing old name → the new `ErrConnNotFound` (removed by another window meanwhile). |
| `web/store.go` | `Conn(name)` does a lookup (it is where a kept DSN comes from). `UpdateConn(old, c)` keeps the old row's `Added`. In one transaction it runs DELETE + INSERT (the name is the PK, so a rename clash fails the INSERT) and, on a rename, `UPDATE tabs SET conn = new WHERE conn = old`. It has a memory-only twin. A missing old name is an error rather than a silent resurrection. |
| `web/conns.go` | `PUT /api/v1/conns/:name` → `handleConnEdit`. An empty DSN is filled by `keepDSN`, which uses the stored DSN as typed, with `${VAR}`s, and refuses it under a different driver. The "does this reconnect" check compares the name, the driver and the **expanded** DSN: retyping the same DSN is not a change, but a `${VAR}` whose value moved is. A reconnecting edit is 409 while `hub.tabsOn` > 0. An `ai_rows`-only edit is allowed, because `workspace/chat.go` reads it afresh per question. The order is config → store (a store failure rolls back with `ReplaceConn`) → `mgr.Drop(old)` → broadcast `conns` with `renamed {from, to}`. `connForm.From` lets a Test from the edit form use the kept DSN. `fileConnRefusal` and `unsavedWarning` were factored out and are shared with add and remove. |
| `web/api.go` | `connInfo.AIRows` (`omitempty`) for the edit form's checkbox. |
| `web/server.go` | The route. |
| `web/pages/workbench.go` | `data-airows` on items. The tooltip reads "right-click to edit or remove". |
| `web/static/js/conns.js` | `openAdd` became `openForm(cur)`. When editing it fills the name, driver and checkbox, shows the DSN placeholder "unchanged — type a DSN to replace it" (the driver's example once the driver changes), sends `from` on Test, PUTs on Save, logs "renamed … to …" / "updated …", and doesn't connect. The right-click menu has Edit… (shown as off, with the reason, for file/demo connections). `draw` carries `data-airows`. |
| `web/static/js/app.js` | `connRenamed(from, to)` moves the page's tabs' `conn` (tabs not shown yet have no workspace, so they don't count as "on" it server-side, and would otherwise save the old name back). It is called from the `conns` event and from the edit response, and is idempotent. |
| `README.md` | The "Adding connections" paragraph now covers *Edit…*. |

## Notes

- History and saved assistant chats keep the old name on a rename. They
  record what happened under the name it had then.
- A window whose event stream is down during a rename misses `renamed`. Its
  unshown tabs keep the old name and fall back to the active connection when
  shown. This is rare and harmless, so it's left as is.
- Harness pitfall, saved to memory: rod's `p.Timeout(d)` is one deadline for
  the whole page chain, not a per-call limit.
