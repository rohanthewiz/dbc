## What changed

### N-132: built-in examples, headless (fork A)

- **`config.FindScript`** now returns a `config.ScriptRef` (a path or an
  example). Lookup order: the cwd, then `scripts_dir`, then a built-in
  example (`.go` optional). Your own script wins over an example.
- **`script.RunSource`** runs the embedded source without writing it to
  disk. `Run` and `RunSource` share a `run` helper. stderr gets
  `running the built-in example X.go (none of that name in <dir>)`.
- **`--check`** resolves names the same way, and prints an example as
  `example:NAME.go`.
- **`dbc scripts`**:
  - It lists the examples no script of yours shadows.
  - New last column `kind` (`script`/`example`). The existing columns keep
    their positions.
  - An example has no modified time: blank in the table, `null` in JSON.
- **Docs.** README, `.claude/skills/dbc/SKILL.md`, `scripting.md`, and the
  `scripts/loop_params.go` header.

### N-134: the assistant in script tabs (fork B)

- **`workspace.ScriptChatContext`.** A script question carries:
  - the source, fenced as `go` and named;
  - the configured connections, as `name (driver)`;
  - the tables named in the script's SQL or in the question;
  - the error or result of this script's own last run.
- **`sdbapi.Summary()`** (`sdb/sdbapi/summary.go`) gives about 8 KB of
  signatures plus one sentence each, sent once per conversation. `apiSent`
  resets on ⟲ new.
- **`ai.Context`** gained `Script`, `ScriptConns` and `ScriptAPI`.
  `ai.Build` frames them.
- **Page.**
  - The chip says "script".
  - The editor menu has "about this query" and "about this script", each
    shown only in its kind of tab.
  - Go blocks get ⤓ insert, which refuses in a query tab.
- **Bug fixed on the way.** A script run left `lastStmt` on the previous
  SQL, so its error or `s.Show` result was attributed to that statement,
  including in the TUI's cats staging. A script run now clears `lastStmt`
  and records `lastScript`.

### N-135: script drafts per window (fork B)

- **Keys.** Drafts are stored as `dbc.script.draft.<owner>:<name>`. The
  owner id lives in sessionStorage, so a duplicated tab gets a new one
  (`dbc.scripts.newOwner()`). Each owner sends a 30 s heartbeat.
- **Opening a script.**
  - This window's own draft wins.
  - Otherwise the newest draft of a closed window (or of the old one-key
    format) is adopted.
  - A live window's draft is never touched.
- **Rename** moves the drafts. Owners that are gone are swept at boot.
- **Judgement call.** When two closed windows both left a draft, the newest
  is adopted and the other is dropped, with a log line.

### N-136 and N-119: TUI (fork C)

- **N-136.** "Result 1 · 2 · 3" on the results title (`tui/resultsets.go`).
  - `[` / `]` in the grid step through the results, and a click on a number
    shows that one, also from the Plan tab.
  - When it doesn't fit, it switches to a compact "Result ‹ k/N ›". It
    stops at the ends rather than wrapping.
  - The Plan tab's label moved into `planTabLabel()`.
- **N-119.** `chipRows` in `tui/connform.go` wraps the TLS chips onto a
  second line, and the form's height counts it. The real threshold was
  about 108 columns, not 75.

### N-120: the e2e "tab groups" step, two app races (fork D)

1. **`tabBody` saved the wrong connection.** It saved the on-screen tab's
   connection from `state.active`, which is stale between `activate` and
   its workspace's answer. It now uses `t.conn`, and `newTab` likewise.
2. **Layout PUTs could arrive out of order.** Quick Ctrl+B presses could
   leave `sideHidden: "1"` stored under an open sidebar. After the reload
   the sidebar was folded, and the clicks landed at (0,0). `dbc.putLayout`
   (`core.js`) now chains the writes in order.

In the e2e:
- A shared `clickAt`/`tabSelector` (`harness_test.go`) replaces fragile
  `MustClick`s.
- Two new checks force each race open, and each fails with its fix
  reverted.
- N-110 had already been closed.

### N-097 and N-126: live MySQL (fork E)

- **The pooled-cancel failure was a real bug.** `connectionID`
  (`db/mysqlkill.go`) did not accept `uint64`, which is how
  go-sql-driver/mysql returns `CONNECTION_ID()`. So a canceled pooled MySQL
  statement was never KILLed: N-089 never worked live. The offline fake now
  returns `uint64` too.
- **`etl/live_mysql_test.go`** (new). It covers:
  - Create, with the exact types created;
  - Truncate as DELETE keeping the old rows on a failed reload;
  - MySQL ↔ Postgres in both directions.
- **`TestLiveWorkspaceCompletionMySQL`** covers N-094's MySQL half without
  a person: the first load, backtick quoting, and a database switch.
- **Postgres `infinity` into a MySQL DATETIME** fails the load cleanly. The
  test pins that behaviour; no mapping was chosen (N-138).
