## N-285: a headless run settles old records by status alone (`57686dd`)

Every headless job or pipeline run calls `Engine.Recover`. It used to
list every head with `ListRuns`, which parses each record whole: the
Rows sum lies deep in the record, and a one-shot process has no head
cache.

New `userdata/runstatus.go`:

- **`RunStatuses`** decodes each record's top-level keys through a 2 KB
  buffered reader and stops at `"status"`. Jobs writes it before the
  pipelines and their logs. A record without it among its first 32 keys
  is read whole.
- **`RunIndex`** maps every id to its file in one pass.
- **`ReadRunAt`** reads a known path, with no glob.

`Recover` now reads statuses, and reads whole only the running or queued
records. `BenchmarkRecoverRead`, over 200 records of 2,000 log lines with
no cache:

| Read | Time | Bytes |
| --- | --- | --- |
| heads (before) | 115 ms | 30 MB |
| statuses (now) | 3.3 ms | 1.2 MB |

No sidecar file was needed.

`dbc runs --sql`:

- The load runs in one transaction on one session.
- The records come through `Engine.Records`, which reads memory first,
  then disk through one `RunIndex`. `Get` became `inMemory`, then
  `fromDisk`.
- A `--limit` given explicitly (`cmd.IsSet`) bounds the load. The
  default 50 does not, since that would change what an existing query
  answers.

Tests: `TestRunStatuses` and `Engine.Records` in the job record test.

## N-287: CLI discoverability (`e85bd30`)

- **`dbc conns`** (`conncmd.go`, alias `connections`). It lists name,
  driver, default and source (config, saved in dbc web/TUI, `--dsn`,
  demo). No DSN is shown, `--format` applies, and nothing connects.
- **`dbc completion bash|zsh|fish|pwsh`**, through urfave/cli's
  `EnableShellCompletion`.
- **`$DBC_CONFIG`** is the env source of `--config`.
- **`$DBC_CONN`** is read in `pickConn`: after `-c` and `--dsn`, before
  `default_connection`. It is not `-c`'s env source on purpose: a `-c`
  that came from the environment would be refused by `copy` and
  `script --check`.
- **Exit 4** (`exitConnect`) when a connection cannot be opened; 1 stays
  for a failed statement.
  - `db.connectErr` marks `openPool`'s error, a bytdb file in use, and a
    failed ping that was not the caller's cancel.
  - The marker goes around the driver's error, inside the serr wrap:
    serr and the logger find an `*SErr` by type assertion on the outermost
    error, so a marker outside it would hide every field.
  - `db.IsConnectErr` reads the marker, and `fail` exits 4 on it.

Checked in the real binary:

- `dbc conns` as text, JSON and CSV.
- `DBC_CONN=other dbc "select …"` runs on `other`, and a `copy` under
  `DBC_CONN` is not refused.
- A refused port exits 4 with its `[conn=dsn op=ping]` fields; a syntax
  error exits 1.
- `dbc completion zsh` prints the script.

Tests: `TestConnectErrMarked` and `TestDBCConnEnv`. The cats manifest's
completions gained `conns`; its test checks them against `newCLI`. The
README and the dbc skill are updated.

## N-293: the keys dialog filters, and the hints follow focus (`2476452`)

**The F1 dialog** has a filter line on its first row.

- Typing narrows the rows to those whose key or description holds the
  text, under their group headings. A group with no match goes, and
  "no key matches" says when nothing does.
- Esc clears the filter first, then closes.
- The letters are the filter's now, so the dialog scrolls by the arrows,
  PgUp/PgDn and Home/End only.

**`focusHints`** gives the status bar one list per pane (editor, grid,
plan, log, connections, tables, assistant). Each list ends with
`F1 keys`.

Tests: `TestHelpFilter`, `TestHintsFollowFocus`, the existing
`TestHelpDialog`, and the TUI pty e2e.
