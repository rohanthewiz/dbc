# TUI ↔ dbc web parity: tabs, rename, transpose, consoles, history, connection form

Session: `2da4f2ce-4f6d-45fa-9aa8-cca85996211c`

## Ask

"Bring the TUI up to feature parity (as much as possible) with the web
interface. Be sure to include all open TUI items in the Next list."

The open TUI items were N-101 (history per database, both UIs), N-102
(rename/delete consoles), N-111 (grid transpose) and N-113 (go to
definition / usages / rename). N-087 and N-104 are by-hand checks and stay
open. A sweep of the README, `web/static/js/*.js` and the TUI found these
further gaps: query tabs, the add/edit/test/remove connection form, a keys
dialog, the sidebar fold, PNG/Mermaid plan saves, and a persisted layout.

## How it was run

Four forked agents worked in git worktrees (`.claude/worktrees/agent-*`,
since merged), one per package:

- A: N-113
- B: N-111
- C: N-102 + N-101
- D: the connection form

Meanwhile the coordinator did the small items, then query tabs once A–C
had merged. Two review agents then checked the tabs and console code and
the `connedit` refactor. Every finding they confirmed was fixed with a
regression test.

## What landed (TUI unless noted)

- **Keys dialog**: `F1` anywhere, `?` outside text fields (`tui/help.go`,
  `keyGroups` data, kept in step with the README by hand).
- **Sidebar fold**: `Ctrl+B`, the `‹` on the Connections box and the `›` on
  the edge (`layout.foldTab`). `Ctrl+L` unfolds.
- **Layout persisted**: `~/.config/dbc/tui-layout.json`
  (`userdata.Layout`). It holds the pane sizes, the fold, and the tabs. It
  is a JSON file like `schema-picks.json`, because that is the TUI's
  existing convention for small state.
- **Plan saves**: PNG and Mermaid `.mmd`. A `.mmd` is logged, not opened.
- **N-113** (`tui/symbol.go`):
  - `F12` / Ctrl+click goes to the declaration.
  - `⇧F12` underlines the uses and steps through them (`F24` is accepted).
  - `F2` renames as one undoable edit, through the shared `promptModal`
    (A's own `renameModal` was folded into it at merge).
  - All three are in the editor's right-click menu.
- **N-111** (`tui/transpose.go`):
  - `t` turns the grid. Only the picture turns, and copies and exports
    follow it (`export.Transpose`).
  - A bug the pty e2e run caught: turning back upright left the view
    scrolled to the cursor's column. The `grid.reveal` pass in `Draw` fixed it.
- **N-102**: the editor menu gets Rename console… / Delete console…
  (`tui/prompt.go` `promptModal`, `loadIntoEditor`).
- **N-101**:
  - `userdata.Entry.DB` holds the console key `host/database`.
  - `HistoryIn` filters by it, and `Workspace.HistoryKey` gives the tab's.
  - TUI: Ctrl+P opens scoped; Tab or the chip switches to every database.
  - Web: `GET /api/v1/ws/:id/history?scope=auto|db|all`, plus a scope
    button and Tab in the dialog.
- **Connection form**:
  - A new package `connedit` holds the form, DSN from fields,
    keep-DSN/keep-password, the check and the test, and add/edit/delete
    with rollback.
  - `web/conns.go` now delegates to it, with the same statuses and texts.
  - TUI: `tui/connform.go`. `a`/`+` adds and `e` edits; the right-click
    menu has Edit/Remove/Add. `✎` and `· tls` mark rows in the list.
  - A rename moves schema picks (`userdata.MovePicks`).
- **Query tabs** (`tui/tabs.go`):
  - `⌥T` / `⌥W` / `⌥1…9`. A strip on the editor's border appears with 2+
    tabs: click switches, double-click renames, right-click opens the menu.
  - Marks: `●` running, `•` done in the background, `◆` stateful. In the
    list, `○` is another tab's connection.
  - The design is a swap: the tab on screen IS the Model's fields (`m.ws`,
    `m.editor`, …), and `park`/`load` swap them.
  - Workspace commands are tagged (`m.tag` → `tabMsg`). `routeTab` queues
    a background tab's events and `arrive` replays them.
  - Release jobs run at once.
  - Ticks carry the tab and a per-visit sequence number.
  - No two tabs share a console (`freeConsole`, `consoleShownElsewhere`).
  - Restored tabs are lazy (`t.lazy`), and the active one connects in `Init`.
  - `Ctrl+C` won't quit over a background run.
- Results title says "1 row".

## Review fixes (after merge)

- **Tabs**:
  - `closeTab` now arrives at the neighbour (queue, marks, lazy connect,
    ticker).
  - `tabTarget` treats lazy and never-connected tabs as on their own
    connection; it is used by `savedTabs`, `tabOn`, `connInUse` and `○`.
  - `tabOn` counts `<conn>/<db>` as holding `<conn>`'s pool.
  - cats is re-reported after a close or a switch, and ticker chains are
    numbered.
- **Connection form**:
  - Test numbers are counted across forms (`Model.connTestSeq`).
  - Lazy tabs follow a rename or remove.
  - Derived picks are matched by the longest base.

## Verification

- `go vet ./...` and `go test ./...` pass.
- **`tui/e2e`** (the real binary in a pty, opt-in with `DBC_TUI_E2E=1`): new
  steps for F1, Ctrl+B, `t`, ⌥T/⌥1/⌥2, F2 and the `a` form, all passing.
- **`web/e2e`**: a new step, "history scoped to the database", passes.
  - "tabs survive a reload" flakes (3 of 10 runs; N-110). The cause is
    pre-existing and outside this work: in a new web tab the typed text
    reaches the tab's buffer but never its console file.
  - A probe showed `console-2` still `{text:""}` 20s after typing, with the
    editor holding the text. The diagnosis is written into N-110, raised to
    medium, and not fixed here.
