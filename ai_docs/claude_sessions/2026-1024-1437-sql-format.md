# Format SQL — and unwrap a query pasted from a log (TUI and dbc web)

Session: `342e8b17-56b8-4856-8aeb-c0d86934b191`

## Ask

From the cats-todo backlog: add a feature to clean up and properly format
a query like this one, copied from a log line:

```text
"SQL query after template replacement:\nupdate lymbic_stg.stg_dim_item set service_account=  (string_to_array(name ,'_'))[1];\n\nwith tmp as\n (\n  select g.*, …"
```

## What was there

- Nothing formatted SQL. The editor had a lexer (`sqlsplit.Lex`) for
  highlighting, and the splitter for statements, but no layout pass.

## Design

- **`sqlsplit.Format`** (`sqlsplit/format.go`), in the splitter's package on
  purpose. It reuses the same scanner (`skipQuoted`, `skipBlockComment`,
  `dollarTag`…), so a string or a comment ends where the editor draws it
  ending — the same reason `Lex` lives there.
- **Unwrap first** (`sqlsplit.Unwrap`), conservatively, so plain SQL comes
  back unchanged:
  - the whole text quoted as a string literal (`"…"` or `'…'`) with escapes
    in it: quotes off, `\n` `\t` `\"` `\uXXXX` undone (`strconv.Unquote`,
    then a manual fallback for `\/` and single quotes);
  - no quotes, but a `\n` outside any `'…'` SQL string: unescaped;
  - prose in front: cut at the first statement word after a colon or at a
    line start. When the text starts with a statement word, only a
    first-line `<words>: <statement word>` label is cut ("Update query:
    update t …"). `label:update` lexes as the parameter `:update` and is
    handled too.
- **Layout**: tokens → a tree on `( … )` and `CASE … END` → each statement's
  top level cut into clauses on a fixed list of clause words. One rule
  throughout: a piece goes on the current line if it fits in 80 columns,
  else it breaks by kind:
  - list clauses (SELECT, SET, GROUP BY, ORDER BY, VALUES, RETURNING): one
    item per line;
  - conditions (WHERE, HAVING, a JOIN's ON): one AND / OR per line, the
    AND of BETWEEN excepted;
  - a `( … )` holding a query: an indented block, `)` back at the left;
    a query of more than two clauses is always a block;
  - any other `( … )` with commas: one item per line; `CREATE TABLE`'s
    column list always;
  - `CASE`: one WHEN / ELSE per line.
  - Words that look like clauses but aren't: IS DISTINCT FROM, FOR UPDATE,
    ON DELETE SET NULL, DEFAULT VALUES, ON CONFLICT … DO UPDATE, LEFT(…),
    WITH not at the start (WITH TIME ZONE).
- Keywords upper-cased (the highlighter's list plus a few clause words),
  except as part of a dotted name (`t.key`). Identifiers, strings, quoted
  names and comments untouched; nothing reordered or dropped.
- The writer has a flat mode used to measure a piece on one line; it marks
  `broken` for anything that cannot sit on one line (a line comment, a
  multi-line string, a subquery of more than two clauses).
- **`sqlsplit.FormatSpan`** keeps the blanks around a selection, shared by
  both UIs.

## The UIs

- **TUI** (`tui/format.go`): `Alt+Shift+F` (a legacy terminal's ESC F
  arrives as the same chord) and the editor menu row **Format SQL** /
  **Format selection**. One `Replace`, so one undo step. With the whole
  buffer formatted, the caret goes to the start of the statement it was
  in, if the statement count is unchanged; else to the top. The log says
  "formatted … · ^Z undoes it" or "already formatted". F1 help, the
  startup keys line, README.
- **dbc web**: `POST /api/v1/format` (`web/grid.go handleFormat`,
  `{buffer}` → `{text, changed}`), registered as Monaco's document and
  range formatting provider for sql/pgsql/mysql
  (`editor.js registerFormatting`). Shift+Alt+F is bound explicitly:
  Monaco's own key is Ctrl+Shift+I on Linux, and its Format Document
  ignores a selection. Menu row as in the TUI; KEYS list.
- Script and pipeline tabs (Go, `dbcjson`) have no formatter; the key does
  nothing there. A first draft of the README claimed Monaco's JSON
  formatting for pipeline tabs — wrong (dbcjson is dbc's own Monarch
  language), corrected.

## Tests

- `sqlsplit/format_test.go`: the log query exactly; layout cases; Unwrap
  cases; and a property test over varied inputs (unbalanced brackets, CASE
  with no END, Postgres operators, MySQL `@var`) that the token stream is
  unchanged and Format is settled (formatting twice changes nothing).
- `tui/format_test.go`: whole buffer + one-^Z undo + "already formatted";
  caret kept on its statement; selection only, trailing newline kept, menu
  row label.
- `web.TestFormat`; web e2e step "format SQL" (`web/e2e/format_test.go`):
  Shift+Alt+F on a pasted log string, one undo restores it, and the menu's
  "Format selection".
- Results: `go test ./...` green. The format and editor-menu e2e steps
  passed 6/6 alone. The full web e2e passed 2 of 3 runs at the end; the
  failure was a nil-pointer panic in "tabs survive a reload". An earlier
  full run failed once in "editor menu" (output lost). Both steps pass
  alone; raised as N-225.
- The README's example was checked to be Format's exact output.
