# N-229: Go snippets for script tabs

Session: `bf932df7-f754-4275-8215-bd8ad9699d68`

## Ask

From the cats-todo backlog, next-list item N-229: live snippets expanded
only in SQL documents (the TUI's editor, dbc web's query tabs). Go snippets
for script tabs needed a language field on `userdata.Snippet`, so a SQL
name does not fire in Go and the reverse.

## Decisions

- **Two languages, `sql` and `go`** (`userdata.LangSQL`, `LangGo`).
  `NormLang` reads "" as SQL (callers that predate languages keep saving
  what they did) and refuses anything else (a snippet in a language no
  document has would never expand).
- **Names stay unique across languages.** The name is the key everywhere —
  the bytdb primary key, `/api/v1/snippets/:name`, a rename — and the
  dialogs list both languages, so one name meaning two snippets would make
  edit/delete ambiguous. Cost: `sel` cannot be both.
- **Schema migration in place**: `ALTER TABLE snippets ADD COLUMN IF NOT
  EXISTS lang TEXT NOT NULL DEFAULT 'sql'` on every open (bytdb supports the
  guarded form and backfills the default). An older dbc's insert gets the
  default, and its upsert does not name `lang`, so its edit of a Go snippet
  keeps it Go. Checked that the per-open DDL does not rewrite the file (it
  would make the TUI and web re-read each other on every Tab).
- **Go starters seeded under their own flag** (`seeded_go`; SQL keeps
  `seeded`), so existing stores get them once; `ON CONFLICT DO NOTHING`
  spares a user snippet of the same name. Starters: `iferr` (mirrored
  `err`), `qry` (`s.Query` + print loop), `exec` (`s.Exec` + count), `each`
  (`$SELECTION$` in a loop over `s.Conns()`). Tab-indented, as gofmt.
- **Dialogs list every snippet** (they are where snippets are kept), the
  editor's language first (across all filter ranks), the other dimmed and
  tagged; a pick of the other language is refused with where it expands.
- **The server re-checks the language on expand** (`lang` in the request;
  400 naming the tab that expands it), since the dialog can pick any row.

  `Snippet.For`, `GetFor`, `ListFor`, schema column + ALTER, per-language
  seeding (`seedKey`, `seedLang`), `lang` in save/query.
- `tui/snippets.go` — `editorLang` (SQL): Tab (`GetFor`), the completion
  popup (`ListFor`) and `pickSnippet` see SQL only; `insertPicked` refuses

  form's Language row (chips, `^L`, placeholder per language).
- `tui/help.go` — the F1 line says SQL here, Go in web script tabs.
- `web/snippets.go` — `lang` on save (400 on unknown) and expand (400 on a
  mismatch); `complSnippets` SQL only.
- `web/static/js/editor.js` — `snippetLang()` ("sql" query tab, "go" script
  tab, "" pipeline/job JSON) drives `dbcSnippetWord`; `lang` sent on

  (main editor's model only, since the expand command acts on it).

- `web/static/js/snippets.js` — `names` is name→lang, `has(n, lang)`,

- `snippet/snippet.go` package doc, README (Live snippets: "SQL and Go",
