## What changed

Four commits on `main` (`6875325` … `a72ccaa`). Each item's closing line in
`ai_docs/todo/next-list.md` has the detail; in short:

**N-265: dbc web saves the server did not take** (`6875325`)

- `saveTrouble`: a tab-row or console save that fails (no answer, an
  error; a 409 still marks the tab lost) puts `⚠` on the tabs it covers.
  It logs one line per bout and reason, and retries every 2 s backing off
  to 30 s, and at once when the event stream reopens (a 400 waits for the
  next edit). "saved again" ends the bout.
- A console's text is kept in localStorage while its saves fail (a new
  drafts.js kit, `dbc.console.draft.`, with the scripts' owner/orphan
  scheme) and is put back by `loadConsole`. If the draft's base is the
  file's revision, the draft becomes the text and is saved. A draft older
  than the file is shown under the file's text as one undo step
  (`showConsoleDoc`), the rule a save's conflict has always followed.
- The pagehide goodbye stays inside the 64 KiB keepalive quota. The
  console goes as its own PUT when it fits, and the release carries the
  tab's save only when it fits. Before, a ~32 KB console made the one
  request fail, so the tabs stayed claimed for the 15 s grace.
  `handleRelease` now releases even when its save is refused.
- `beforeunload` asks only when text would be lost.

**N-266: the event stream and the log** (`aaf335f`)

- The window's SSE hub drops a full client at its first missed event
  (`MaxDropped: 1`). Before, rweb's count of drops in a row was reset by
  any send that got through, so one or two lost events went unnoticed: no
  reconnect, no resync, and a tab could stay busy.
- `web/journal.go` numbers each log line per window (`seq`), stamps it
  (`at`) and keeps the newest 1,000 lines or 1 MiB.
  `GET /api/v1/win/:id/log?after=N` returns the lines after N. Whenever
  the stream opens, the page (`catchUpLog`) draws the lines it has not
  drawn, each once, in order, at its own time. So the log survives a
  reload, and a reconnect fills its gap.
- The log scrolls once per animation frame, not a forced layout per line.
- The window's own "log" events (the assistant's) had no case in
  `onEvent` and were never shown; they now are.

**N-267: headless exports** (`b7a68c7`)

- `--max-rows N` (`0`: no cap); a negative N is a usage error, said on
  stderr, since the cli package does not print a flag Action's error.
- The collected output's write to stdout is checked: exit 1, not 0, with
  a short file.
- With no config file, `config.LoadDemo` records where it looked
  (`Searched`). A run on a demo connection then says so once on stderr,
  unless `--demo`, `-c` or `--dsn` asked for it.
- `cats-plugin.toml` completions list the flag (the manifest test caught
  it).

**N-268: a run that ignores its stop** (`a72ccaa`)

- jobs: a `watchdog` per run on the context whose end means stop (Cancel
  or Close; for a job also the policy timeout and on_failure stop). A run
  still going `AbandonAfter` later (default 1 min) is abandoned: the
  record ends failed and says why, and the holds and the overlap slot are
  let go. `finish` runs once; a late goroutine's lines, events and
  progress are dropped.
- headless: the first SIGINT/SIGTERM cancels, a second exits 130 at once.
  If the run is still going 2 s after the first, dbc says so.
  `signal.NotifyContext` swallowed every later signal.
- yaegi's stop (`EvalWithContext`'s unexported `stop()`) is not used. It
  ends every frame of an interpreter, user plugins share one interpreter
  across runs, and reaching it means swapping `interp.done` under running
  frames.
- Raised **N-310**: a TUI or dbc web script run that ignores Stop has no
  backstop.
