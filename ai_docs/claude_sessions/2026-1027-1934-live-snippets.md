# Live snippets — name+Tab, stops, mirrors, $SELECTION$ (TUI and dbc web)

Session: `bc6fc032-bc0c-4229-b54b-b7f3b0113f14`

## Ask

"Help me create a system of live snippets where the snippet code can have
certain $VAR[n]$ replaceable params with $SELECTION$ standing for the
selected text."

The user's choices, asked up front:
- **Storage:** a bytdb store with a management UI. This was their global
  default, picked over a hand-edited `snippets.toml`.
- **Trigger:** both the abbreviation (a name then Tab) and a picker.
- **Syntax extras:** all three offered: `$END$`, defaults (`$VAR1:id$`),
  and `$$` for a literal `$`.
- **Scope:** TUI and dbc web in one pass.

Then: commit, `/next-list`, `/sess-wrap`.

## What was there

- **No snippets anywhere.** The TUI's editor (`tui/editor.go`) is dbc's own.
  Tab is the app's focus key (`tui/app.go` `cycleFocus`) and the
  completion popup's pick.
- **dbc web is Monaco.** It has a snippet engine built in
  (`snippetController2`: tab stops, mirrors, `$0`).
- **One bytdb store today,** dbc web's `web.bytdb`. It is held open for the
  process's life, and bytdb's lock is exclusive.

## Design

- **`snippet` package** (new, pure). It is the single expander for both
  UIs.
  - **`Parse`:**
    - `$VARn$` and `$VARn:default$` (n from 1 to 999), `$SELECTION$`,
      `$END$` (at most one), and `$$`.
    - Any other `$` is literal, so `$1` and `$tag$` need no escaping, but a
      `$$` dollar quote must be written `$$$$`.
    - A `$VAR` followed by a digit has to be a well-formed stop; otherwise
      it is an error. A bare `$VAR$` or `$VARIANT` is text, since a dollar
      tag may be named that way.
    - A default is one line.
  - **`Expand(t, Context{Selection, SelPrefix, Indent})`:**
    - Returns `Expansion{Text, Stops (by N), End}` as byte offsets.
    - The body's later lines get the insert line's indent.
    - A stop's default is the first one written among its uses.
    - A multi-line selection keeps its relative indentation under the
      placeholder's line (`placeSelection`). `SelPrefix` says whether the
      selection started in its line's indentation.
    - A selection's trailing newline is kept after the expansion, and
      `End` stays before it.
  - **`Expansion.Monaco()`:** renders Monaco's syntax.
    - `${n:text}` for every use (Monaco mirrors equal numbers), `$0` at
      `End`, with `\`, `$` and `}` escaped.
    - An empty mark sorts first at a tie, so `$END$$VAR1:x$` comes out as
      `$0${1:x}`.
  - **`ValidName`:** letters, digits and `_`, at most 40 characters. A
    name is typed as one word.
- **`userdata.Snippets`** keeps them in `~/.config/dbc/snippets.bytdb`.
  - It opens, works and closes for each operation (`withDB`), retrying on
    `bytdb.ErrLocked` with backoff for up to 1s. Then it fails with
    `ErrSnippetsBusy`. The TUI and dbc web may both run, so neither can
    hold the file.
  - `List` is cached on the file's size and mtime. The cache is checked to
    work: a read-only open leaves both unchanged, so a Tab costs a stat.
  - `Save(old, s)`:
    - Is a new snippet (`old` ""), an edit, or a rename.
    - Refuses `ErrSnippetExists` and `ErrNoSnippet`.
    - Checks the name and the template first.
    - Makes the description one line.
  - `Delete`.
  - A `meta.seeded` flag, set in the same transaction, seeds five starters
    once: `sel`, `cnt`, `cte`, `countof` and `upd`. A deleted starter
    stays deleted.
  - `OpenSnippets("")` is a memory-only store, used by tests and by
    NoPersist.

## TUI

- **`tui/snippets.go`:**
  - **`snippetKey`** runs in `key()` before the completion popup and the
    chords.
    - **Tab with no session:** `wordBeforeCaret` must be an exact snippet
      name, with no selection, the caret at the word's end and no `.` in
      front. Then it expands, beating the popup. Any other word falls
      through to the popup or the focus cycle.
    - **Tab in a session:** yields to an open popup (its Tab picks), else
      goes to the next stop. Shift+Tab goes back. Esc ends the session,
      once the popup is closed.
  - **`insertSnippet`:**
    - It normalizes tabs to four spaces before parsing, as the editor
      stores them, so the offsets stay right.
    - The expansion is one `Replace`, so one undo step.
    - It starts `snipSession` on the editor.
  - **`snipSync`** runs once per `Update` (`app.go`), so every source of
    change is covered: keys, paste, a completion's pick, undo, clicks.
    - It ends the session when the caret leaves the current stop.
    - `snipAbsorb` accepts two shapes of change:
      - An edit to the first use only: the head and tail are intact, the
        rest becomes the new value, and the mirrors are rewritten
        without a checkpoint.
      - The same change to every use (undo or redo of mirrored typing):
        the length change splits evenly between the uses, and
        `rebuild(val)` must equal the new text.
    - Anything else ends the session.
  - `SetText` and `Restore` clear the session.
  - `editor.Draw` lights and underlines the current stop, and underlines
    the stops still to come.
- **`tui/snippetdlg.go`:**
  - The **Alt+S dialog** filters as you type, ranking exact and prefix
    name matches first. Rows are marked ⇲ (uses the selection) or ⚠
    (does not parse), and the body of the row under the cursor is shown
    below the list.
  - Enter inserts. ^N is new, with the filter's text as the name when it
    is valid. ^E is edit, ^D is delete behind a confirm menu. A
    right-click menu offers the same.
  - With a selection, the title says a pick wraps it.
  - **`snippetForm`** has name, description and body fields. Tab changes
    field, Enter in a one-line field moves on, and ^S saves. A refusal
    stays in the form with the reason, and a save goes back to the dialog
    on the snippet.
- Editor menu row **Insert snippet…** / **Surround with snippet…** (⌥S).
  F1 help, and the startup keys line.

## dbc web

- **`web/snippets.go`:**
  - `GET/POST /api/v1/snippets`, `PUT/DELETE /api/v1/snippets/:name`.
  - `POST …/:name/expand {selection, selPrefix, indent}` →
    `{snippet (Monaco), text, stops}`.
  - A bad name or template is a 400 with the reason; a taken name or a
    busy file is a 409.
  - A `"snippets"` hub event goes out on every change.
  - `Options.Snippets`; `webcmd.go` passes the TUI's file.
- **`editor.js`, "live snippets":**
  - The context key `dbcSnippetWord` is set as the caret moves, and only
    in SQL documents (no fixed language).
  - `Tab` is an `addCommand` with `when: dbcSnippetWord && !inSnippetMode`.
    This was checked to beat the suggestion widget.
  - `expandSnippet` posts the request, then refuses with a log line if the
    model moved while it waited. Otherwise it inserts through
    `snippetController2.insert` with `adjustWhitespace: false`, since the
    server already indented it.
  - `api.insertSnippet` is the dialog's pick, wrapping the selection.
    `expandPlain` covers the textarea before Monaco loads.
  - Alt+S is bound in Monaco and page-wide (`app.js`).
- **`snippets.js`** (new, loaded before `app.js`):
  - Holds the list and the names Tab may expand. It refreshes at load and
    on the hub event.
  - The dialog mirrors the TUI's, with the history picker's CSS plus
    `.sn*` classes.
  - The dialog's keys are Alt+N, Alt+E and Alt+D, matched on `e.code`:
    the browser keeps Ctrl+N, and a Mac's Option types characters.
  - The form saves on Ctrl+S, and on Enter in a one-line field. Esc goes
    back.
  - Delete asks first.
- Editor menu row; the KEYS list.

## Found on the way

- **The first undo test was wrong about the behaviour.** Replacing the
  selected default is its own undo step. Undo restores every use at once,
  so the first-use-only check refused it and ended the session.
  `snipAbsorb` gained the "same change to every use" shape. The test now
  steps ^Z back to "q", then "column", with the session alive, and
  finally to before the expansion.
- **A TUI e2e step can't rely on earlier editor text.** An earlier step
  leaves another query tab active, so the snippets step opens a fresh tab
  with ⌥T.
- **`5f4ad40`** (catalog_timeout, the same day, no session doc) corrected
  N-106's premise during `/next-list`.
