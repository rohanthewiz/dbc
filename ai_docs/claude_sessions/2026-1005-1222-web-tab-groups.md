# Web query-tab groups, as in ced

Session: `b3487585-2aac-40b4-b54d-eff59b657654`

## Ask

From the cats-todo backlog: "Allow us to group console tabs as we do in
~/projs/go/ced/". In dbc the console tabs are dbc web's query tabs (each
tab shows a console of its database). ced's design is
`internal/app/tabgroups.go` + the "Tab groups" rules in ced's CLAUDE.md.

## Design (ported from ced)

- **Two kinds, one record.** A **connection group** is a rule. Every tab
  on its connection belongs, and so does any tab on one of the
  connection's other databases (`prod/analytics`, the derived connections
  the database picker opens). That includes tabs that switch to it later.
  It is ced's folder group with the connection standing in for the folder.
  An **ad-hoc group** is a hand-picked set of tabs. `conn == ""` means
  ad-hoc.
- **One group per tab, resolved, never stored on the tab.** `groupOf`
  checks ad-hoc membership first. After that, the deepest connection
  group that hasn't excluded the tab wins. Removing a tab by hand from a
  connection group adds an exclusion.
- **Membership is by saved-tab key**, because keys survive a reload.
- **Contiguity comes from reordering the `tabs` array** (`arrange`, run at
  the top of every `renderTabs`). It is stable, and does nothing with no
  groups. The order is saved only when a tab actually moved.
- **Collapse** hides members but never the active tab. The chip then
  reads `name +N`.
- **Chip gestures:** a click folds the group, and a right-click opens the
  group menu. That menu has Collapse/Expand, Rename…, Make ad-hoc group,
  Close group's tabs, Ungroup, and the member tabs as rows to jump to.
  ced's "Switch to a tab in group…" picker is inlined here as those rows.
- **Tab right-click menu:** Add to group… (existing groups, New ad-hoc
  group…, New connection group: <conn>), Remove from group X, and
  Group X…
- **Deviations from ced:**
  - Names are up to **8** letters or digits rather than 4. ced's limit
    comes from sharing a terminal row; the browser strip has more room.
  - A new tab opened from a tab in an ad-hoc group joins that group, as
    browser tab groups do.
  - "Close group's tabs" keeps any tab whose session may hold state, and
    never closes the window's last tab. This replaces ced's rule of
    keeping dirty tabs.
- **Colours:** six group hues per theme as `--g0…--g5` in `app.css`. The
  theme palette has only accent, warn and err. Chip text is `var(--bg)`.
  Members get an inset 2px underline in the group colour.

## Persistence (`web/groups.go`)

- The layout key `groups` holds a JSON array of
  `{name, conn?, members?, exclude?, collapsed?, color}`. It sits beside
  `tabs` and `plans`, and is rewritten whole by `saveGroups`.
- The page's `encode` writes only the keys of tabs this window shows.
  `restore` drops keys this window didn't claim, and drops an ad-hoc group
  left with no members.
- **Cross-window merge:** `handleSaveLayout` now passes `groups` through
  `mergeTabGroups`, the counterpart of `mergeTabKeys`. For old groups'
  member and exclude keys that another live window holds:
  - if the writer has a group of the same name (compared
    case-insensitively), the keys are merged into it;
  - otherwise the old group comes back with only those keys.

  Its limit is recorded as N-109.
- **Connection rename:** `moveGroupConns`, called from `handleConnEdit`
  next to `moveSchemaPicks`, moves stored groups on `from` and
  `from/<db>`. On the page, `connRenamed` calls `groups.renameConn`.
  `renamedConn`'s row check was factored into `derivedConn`, which also
  backs the groups' `connUnder`.
