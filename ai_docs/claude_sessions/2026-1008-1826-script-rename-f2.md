# Script tabs: Rename (F2), scope-aware

Session: `c4822f76-a1d8-481c-9062-b27e654b4631`

## Ask

1. Dropped in from the cats-todo backlog: N-164. Add Rename (F2) to dbc
   web's script tabs, built on `script.Resolve`'s scope-aware uses. Refuse
   an imported member (`s.Query`), a builtin, or a new name already taken in
   that scope (go/types' `Scope.LookupParent`). Mirror the SQL editor's
   rename provider (`editor.js` `registerSymbols`).
2. `/sw` (sess-wrap).

## Decisions

- **Two checks: a scope check, then a recheck.** The scope check gives the
  common refusals in plain words. `Scope.Lookup` runs at the declaring
  scope, and `LookupParent` runs at every use to find a block in between
  that declares the new name. Package scope and file scope (imports) are
  checked against each other, since Go treats them as one namespace though
  go/types keeps two scopes. The recheck type-checks the renamed text again.
  Every ident must bind as before (matched by its declaration's offset, with
  edited offsets mapped back to the original) and no error may appear at a
  new place. That catches what scopes cannot see: a field or method
  colliding on its type, a promoted field newly shadowed, and an outer
  name's uses captured by the renamed one. It costs a second check of a
  small file (under 1 ms).
- **Which message wins when both fire.** A capture usually also leaves a
  variable unused, so the binding sentence ("x on line 9 would then mean
  the one declared on line 8") is preferred. The exception is a binding
  lost to nothing: that is a declaration the checker refused (a duplicate
  field), so its compile error ("B redeclared") is the reason given.
- **Refused up front through `Symbol.Fixed`, so the box never opens.**
  - an imported member
  - a builtin
  - the script's `Run`, which dbc calls by name
  - an embedded field
  - a type that something embeds

  The SQL editor's `s.fixed` already works this way. Embedding was left out
  on purpose: the field is named after the type, so a rename would have to
  reach into other structs' selectors too, and doing it by hand is clearer.
- **An unnamed import gets a name.** Renaming `sdb` inserts `db ` before
  the path literal (an insertion edit, `From == To`).
- **Refactor, not a copy.** `symbol.go`'s parse and check moved into a
  `checked` struct (`checkSrc`, `key`, `resolve`) that `Resolve` and
  `Rename` share. It now also records `Info.Scopes` and the checker's
  errors. `Resolve`'s behaviour is unchanged and its tests pass as they
  were.
- **Route.** `POST /api/v1/script-symbol-rename` takes `{text, caret,
  name}` and answers `{edits}` in UTF-16 units. A refusal is a 400 carrying
  the sentence, as the SQL `…/rename` does. It sits beside `script-symbol`,
  not under `/api/v1/scripts/`, to stay clear of the radix-router issue
  documented in `web/scripts.go`.

## Changes

- `script/rename.go` (new):
  - `Rename`, `Edit`, `NotOnSymbol`
  - `checked.fixed`, `declScope`, `taken`, `recheck`
  - `applyEdits`, `backMapper`
- `script/symbol.go`: the `checked` refactor, plus `Symbol.Fixed`. A member
  gets its Fixed sentence in `resolve`.
- `script/rename_test.go` (new):
  - 11 renames: shadowed err both ways, field, method, type switch,
    label, unnamed and named import, trimmed name, shadowing an unused
    outer name, a local named like an imported type's literal key
  - 19 refusals, covering every reason
  - `TestResolveFixed` and `TestBackMapper`
- `web/scripts.go`, `web/server.go`: `handleScriptSymbolRename`.
  `scriptSymbolReq` gained `Name`.
- `web/scripts_test.go`: `TestScriptSymbolRename`, covering UTF-16 edits
  past a non-BMP rune and a 400 for a taken name.
- `web/static/js/scripts.js`: `registerRenameProvider("go")`
  (`resolveRenameLocation` + `provideRenameEdits` with `versionId`), and
  the header comment's RENAME paragraph.
- `web/e2e/scripts_test.go`: F2 on the outer `n` of the shadowing script
  renames its two uses and not the if's own `n`. F2 on `s.Print` shows the
  refusal and no box.
