## N-156: the live notices test, and what a DO's write line says

`TestLiveWorkspaceNotices` wanted three notes. Since N-155 it got five:
each `DO` block's notice, then a line "statement 1/2: 0 affected — DO …".

- **Decision: keep the line, but say "done".** "0 affected" was false. A
  DO block or a CALL may write any number of rows, but Postgres's
  command tag (`DO`, `CALL`) carries no count, so the driver says 0.
  MySQL's CALL reports only the last inner statement's count. The line
  itself is useful: it says the statement ran, and sits between the
  notices it raised. `countless(stmt)` (DDL, DO, CALL) now picks "done",
  as DDL already got.
- **Found on the way.** The fold line's total added a DDL's count,
  though its comment said it did not. On SQLite that count is the
  INSERT's before it (`sqlite3_changes`), so a folded `CREATE TABLE`
  inflated the total (4 where 1 was right). A countless write now adds
  nothing.
- **The repaired test** expects all five notes, in order.

## N-200: a go node's s.Path uses the run's files_dir

A `go.action` or `script.run` node got the session that ran the
pipeline, so its `s.Path` and `s.Export` used the host's files_dir. When
a script passed `PipelineOpts.FilesDir`, the run's file nodes used that
directory while the node's own files did not.

- **An optional host interface.** `pipeline.FilesHost` is `Host` plus
  `ForFiles(dir) Host`, so `pipeline` still needs no `sdb`. `pipeline.Run`
  asks it once, with `Options.FilesDir`, and every node's `Env.S` is the
  answer. A host without it (test fakes) is used as is.
- **The view is a copy of `S`.** `S` could not be copied because it
  holds a mutex and the open Readers/Writers. The state a view must add
  to moved behind a pointer, `S.st *shared`: the openSet for `Release`
  and the catalog record for `CatalogChanged`. A copy is now safe, and
  what a view records is the host's. `ForFiles` returns the session
  itself when the directory is already its own.
- **The API summary is unchanged.** `ForFiles` is host-only
  (`sdbapi.hostOnly`). api.json was regenerated, for `Path`'s doc.
- **Nested runs inherit.** A nested `s.RunPipeline` inside such a node
  defaults to the view's files_dir, so it gets the run's directory.

## N-180: unknown keys kept through a canvas edit

- **Decision: keep them, don't refuse the edit.** A canvas edit
  rewrites the text from what the canvas knows (`specText`, `jobText`),
  which dropped a typo like `"on_eror"` silently. The item offered two
  fixes. I kept the keys rather than refuse canvas edits: refusing would
  block all canvas work over one typo, and a kept key stays named by the
  check ("unknown field") until it is fixed in the JSON view.
- **`keepRest(o, from, known)`** sits beside `sorted` in both kits, which
  already duplicate that helper and `SCALARS`. It appends unknown keys
  after the known ones, in the file's order, at every level rewritten:
  - the pipeline or job, a param, a fragment, a node;
  - a step, the triggers, the policy.
  `cfg` and `ui` are free maps already.
- **Checked:** neither kit stores transient state on spec objects, so
  nothing of the page leaks into the file.
- **A flaky check fixed.** N-193's F2 e2e check failed about one run in
  six: it typed before Monaco had focused the rename box. It now focuses
  the box and waits; 6 of 6 runs passed after.
