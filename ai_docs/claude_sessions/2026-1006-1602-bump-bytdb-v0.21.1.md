# Bump bytdb to v0.21.1: dates copy into bytdb (N-128)

Session: `d422360d-20aa-45ed-88cc-067de08a117f` (same session as, and
follows, `2026-1006-1535-numeric-to-bytdb-and-date-fix-upstream`)

## Ask

"Update dbc to bytdb v0.21.1". That release carries the upstream N-128
fix: `bytdb.ParseDate` accepts timestamp text and keeps the date as
written, so the `time.Time` that bytdb's driver binds as UTC timestamp text
now loads into a date column.

## Changes

- `go.mod` / `go.sum`: `github.com/rohanthewiz/bytdb` v0.21.0 → v0.21.1
  (`go get`, then `go mod tidy`; nothing else moved). Neither
  `tui/e2e` nor `web/e2e` requires bytdb, so neither needed a bump.
- `TestCopyDateToBytdbCreates` (`etl/copy_test.go`): SQLite `DATE` and
  `TIMESTAMP` columns (a pre-1970 date, NULLs in each) copied into bytdb
  with `Create`. The expected rows are written out, not compared with the
  source's: bytdb hands dates back as `YYYY-MM-DD` strings, while SQLite
  gives `time.Time`.

## Tests

- `TestCopyDateToBytdbCreates` passes on v0.21.1. With `go.mod`/`go.sum`
  stashed back to v0.21.0 it fails with "invalid input syntax for type

- `go vet ./...`, `go build ./...` and the full `go test ./...` (with
  `CATS_*` stripped) pass.
