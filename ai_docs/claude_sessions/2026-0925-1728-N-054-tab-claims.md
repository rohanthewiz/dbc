# Saved query tabs claimed per window (N-054)

Session: e67b9287-a7f6-4c54-aa96-71181e2a81d5
Date: 2026-09-25

## Ask

Next-list item N-054: two browser tabs of `dbc web` are two windows over the
same saved query tabs (`web.bytdb`), so editing one tab's text in both loses
the earlier save (last write wins). Fix: a window claims the tabs it shows,
and a second window gets fresh ones.

## Changes (`771cfbf`)

| Piece | Change |
|---|---|
| `web/claims.go` (new) | The hub keeps `claims`: saved-tab key → window. A claim stands while its window is **live**: it exists, has not released, and has a stream attached or had one within `claimGrace` (15 s — covers a reload or an EventSource retry). Liveness is checked when a claim is contested, not maintained. `claim`, `claimBoot`, `claimOne`, `unclaim`, `release`, `heldElsewhere`, `mergeTabKeys`. |
| `web/hub.go` | `hub.claims`/`claimGrace`; `window.detached` (atomic unix-nanos, stamped by the SSE hub's `OnDisconnect` — which rweb calls under its own lock, so no `ClientCount` there) and `window.handedOff` (the page said goodbye). The reaper drops a forgotten window's claims. |
| `web/api.go` | `PUT /api/v1/tabs/:id?win=` and `DELETE …?win=` go through `claimOne`: a tab another live window holds → 409. An unknown or empty `win` claims nothing but is still turned away from a held tab. `PUT /api/v1/layout?win=` merges `tabs` and `plans` with the keys other live windows hold (only when some window does). |
| `web/server.go` | Routes `POST /api/v1/win/:id/tabs` (claim: `{keys?, boot?}` → `{tabs, claimed, held}`) and `POST /api/v1/win/:id/release` (`{save?}`: the last save, then the release — one request so the save cannot land after the release and re-claim). |
| duplicate tabs | A duplicated browser tab copies sessionStorage and so arrives with the original's window id. A `boot` claim on a window with a stream attached and no release is refused (409); the page then opens its own window. A reload passes because its pagehide released first; a window's first page claims before its stream attaches. |
| `web/static/js/app.js` | Boot now gets the window first (reattach, or open), then claims; shows the claimed tabs in saved order, or a fresh tab (new key, never `"1"`) with a log line when others hold them. Saves/deletes/layout carry `?win=`; a 409 save marks the tab `lost` (⊘, italic title, warning; no longer saved; closing it leaves the saved copy alone). `pagehide` → release with the active tab's save; `pageshow` (bfcache) and `resync` → `reclaim` of the non-lost keys. `forgetSession` clears by prefix. |
| `web/static/css/app.css` | `.qlost`, `.qtab.lost`. |
| docs | README's query-tabs paragraph; `Store.Layout`'s "opaque values" note; the hub's lifecycle diagram. |

  from B is marked lost and its stale edit not saved.

## Notes

- A lost tab is not re-claimed automatically when the other window closes:
  its text may be older than the saved one; a reload fetches the saved copy.
- Two brand-new windows on an empty store could still both mint a fresh tab;
  keys are `Date.now()` base-36, so they do not collide in practice.
