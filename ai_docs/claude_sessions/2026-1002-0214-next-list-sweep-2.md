## What was done

### N-091: one EventExit per chat (`ai/chat.go`)

`TestChatSignInThenQueuedQuestionGoes` flaked because `ai.Chat` could send
**two** `EventExit`s. When session/new was refused, `connect` closed the
connection and sent the explained error (the one matching
`ErrAuthRequired`). Closing also ended the rpc read loop, whose `onExit`
sent its own bare "Copilot exited". The two raced. The web pump (and the
TUI) stop at the first exit, so sometimes the sign-in offer never came.

```
transport ends ──► onExit ──connecting?──yes──► record lost/lostErr; connect decides
                                       └──no───► exited(err)
handshake fails ──► claimExit, close, send the explained error
handshake ok but lost ──► exited(lostErr)
```

`connecting`, `lost`/`lostErr` and `exitSent` (via `claimExit`) make exactly
one exit, as the `Events` doc always promised. `ai/exit_test.go` (300
rounds, external package so it can use `aitest`) fails on the old code at
round 0.

A second flake turned up while repeating the chat tests:
`TestChatStaleViewWithHiddenColumnsIsRefused` sometimes failed TempDir
cleanup ("directory not empty"). `assistant.close` saved, but an event
already in the pump could save again after it. A new `closed` flag makes
`onEvent`, `saveLocked` and `ensureLocked` no-ops after close.

### N-090: recount every tab on the connection (`web/hub.go`, `workspace/run.go`)

A RunDone carrying `Counts` now also calls `Server.recountOthers`, which
asks every other query tab (any window) for `Workspace.Recount(conn)`. That
returns nil unless the tab's sidebar shows conn's tables. `Recount` shares

Manager's row-count cache. The writer's `landRun` already did that, so the
other tabs share one counting (`RowCounts` waits for one in flight). Covered by
`TestWriteRecountsOtherTabsOnTheConnection`, which fails without the

### N-093: `tui/e2e` (new nested module)

The old driver was lost with its scratchpad, so it was rewritten. It is
modeled on `web/e2e`: a separate module (creack/pty, charmbracelet/x/vt) so
nothing enters dbc's go.mod, and skipped unless `DBC_TUI_E2E=1`.

```
dbc ──pty──► io.Copy ──► emulator (the screen the test reads)
 ▲                          │
 └──pty◄── io.Copy ◄────────┘  replies to the app's queries; keys and
                               SGR mouse encoded per the app's modes
```

It has seven steps, each read off the screen:

1. Startup draws the panes and shows the row counts.
2. Ctrl+R runs a query into the grid.
3. Completion: `c.` → `br` → Tab gives `c.breed`.
4. A double-click previews a table.
5. A header click sorts, and a second click sorts descending.
6. A click switches connection.
7. Ctrl+Q quits.

It took about 4s per run and passed 3/3. The README's Tests section now
lists three opt-in suites.

### N-089: KILL canceled pooled MySQL statements (`db/mysqlkill.go`)

Every MySQL pool now opens through `mysqlKillConnector`: `openPool` always
uses a connector for MySQL, no longer `sql.Open`. Each connection:

- learns `CONNECTION_ID()` when dialed;
- forwards every interface database/sql looks for (PrepareContext,
  BeginTx, Exec/QueryContext, Ping, ResetSession, IsValid,
  CheckNamedValue);
- remembers its last statement's context.

When database/sql closes a connection that the driver already dropped
(`!IsValid`) while that context was canceled, `Close` sends `KILL <id>`.
The KILL goes over a **fresh dial** from the inner connector, never the
pool: the dying connection is still counted against `SetMaxOpenConns`, so
waiting on the pool could deadlock. Doing it at Close catches cancels
during row streaming without wrapping Rows or Stmts.

Sessions changed too. `learnKillID` takes the id from the wrapper (no
round trip), and `reapCanceled` marks the connection reaped, so no second
KILL is sent. `driverConn` unwraps for code that needs the driver's own
connection.

Tests:

- `TestMySQLKillConnKillsACanceledPooledStatement` (a fake connector with a
  pool of one): checks the KILL, and that healthy closes send nothing.
- `TestLivePooledCancelReachesServer`: passes on Postgres; not yet run on
  MySQL (N-097).

### N-088: peek at a MySQL session's socket (`db/mysqlsock.go`)

`mysqlNetConn` reads go-sql-driver's unexported `mysqlConn.netConn` with
reflect plus unsafe, inside `sql.Conn.Raw`, which holds the connection
exclusively. The lookup matches package, type name and field type, so a
rename returns nil (back to the idle-threshold behavior) rather than a
crash. `Session.quiet` uses it, so a cut within `sessionPingIdle` is found
before the next statement on MySQL as on Postgres.

`TestMySQLNetConnFindsTheSocket` connects the real driver to a fake server
(a v10 handshake, then OK) and sees its hang-up through `sockQuiet`. It is
also the test that fails on a driver rename. The MySQL skips of the "at
once" live cases are removed.

### N-094: completion and search_path; live Postgres checks

The defect the item named was fixed:

- `Manager.SearchPath` reads `unnest(current_schemas(false))` (Postgres
  only), loaded with the completion schema and stored in `complState.path`.
- `Request.SearchPath` carries it into `sqlcomplete`.
- `completer.bare` inserts a table bare when its schema is on the path and
  no earlier path schema has a table of the same name; `resolve` follows
  the path for bare names. With no path, public is the path, as before.
- The old `dialect.bare` was removed; its only two callers were replaced.

The `stringRows` bound error now reads "the catalog is too big to read
whole". The old "…to diagram" was odd under completion's "completion is
without the schema:" prefix.

Tests:

- `TestSearchPath` (unit).
- `TestLiveWorkspaceCompletionNames` (live): qualification, quoting
  (`"MixedCase"`, `"Amount"`), and `search_path=dbc_live_wsc,public` set
  through the DSN (pgx passes it to the server as a setting), including a
  shadowed public table.
- `TestLiveWorkspaceCompletionBigCatalog` (opt-in `DBC_LIVE_BIG=1`):
  240,000 column rows load in about 0.2s; 260,000 fail, and completion goes
  on with the vocabulary.

The README describes the search_path rule.
