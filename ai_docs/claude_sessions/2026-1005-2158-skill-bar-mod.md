# skill-bar: a Claude Code mod with buttons for frequent skills

Session: `a4c873ca-242f-47c2-ae30-d164b5a33cf4`

## Ask

"Create a mod that shows my frequently used skills: /sess-wrap, /clear,
/sess-load". Then, in turn: make the buttons run the commands directly, add a
confirmation before /clear, and use number keys 1 2 3.

No dbc code changed this session. The mod lives outside the repo, in
`~/.claude/mods/skill-bar/`, and every session loads it (see Location below).

## What it is

A Claude Code plugin of function hooks (the `plugin-authoring` skill), drawn as
a band above the prompt via a `ui.render` hook on `{ component: 'AbovePrompt' }`:

```
Skills  1: /sess-wrap  2: /clear  3: /sess-load
```

Files:

- `.claude-plugin/plugin.json`: name `skill-bar`, version `0.2.0`, and
  `"types": "./types/index.d.ts"`.
- `hooks/hooks.json`: `{ "modules": ["./register.tsx"] }`.
- `hooks/register.tsx`: the module. The shortcuts are a `SHORTCUTS` list at
  the top (`name`, `hotkey`, optional `confirm`).
- `types/index.d.ts`: the `$.state` contract, `'skill-bar': { pending:
  SkillBarPending }`, where `SkillBarPending` is `string | null`.
- `tests/skill-bar.test.ts`: 4 tests for `claude plugin test`.

## How it evolved

1. **Fill the prompt.** The first cut used `$.prompt.fill` to put `/<name> `
   in the box for the person to send. It refused to overwrite a draft and
   showed a toast instead. Letter hotkeys (`w`/`c`/`l`).
2. **Run directly.** At the user's request, a press now calls
   `$.command.run({ command })`, which is the same as typing `/<name>` and
   pressing Enter. The call isn't awaited, because it resolves only once the
   command has finished (for `/sess-wrap`, a whole model turn). A rejection,
   such as an unknown name, goes to a toast. The engine queues the run until
   the session is idle, so a press during a turn waits instead of interrupting.
3. **Confirm /clear.** A `confirm: true` shortcut writes its name to the
   `pending` atom, and the band redraws as `Run /clear?  Yes  Cancel`. The
   other shortcuts are hidden while it asks. Yes clears `pending` before
   running. `pending` is kept in `$.state` rather than a module variable, so
   it redraws the band and survives a hot reload.
4. **Digit hotkeys.** The user typed `w` into the prompt expecting it to press
   the button. Letter hotkeys only fire while the band holds the focus (a click
   or ctrl+x tab). A bare digit in an EMPTY prompt box presses a band Button,
   so the shortcuts moved to `1`/`2`/`3`. The confirmation row went to digits
   too, because after a digit press the focus stays in the prompt box and
   `y`/`n` would just be typed. `confirmKeys` gives Cancel the asking
   shortcut's own digit and Yes a different one (`1`, or `2` if the shortcut
   is on `1`), so a double-tap of `2` asks and then cancels.

   Trade-off, accepted: a prompt can't start with 1, 2 or 3 typed into an
   empty box.

## API notes learned (Claude Code 2.1.290 plugin engine)

- Op events answered in a test (`prompt.read`, etc.) return `{ value: ... }`.
  A bare object is skipped with "returned neither { value } nor { deny }".
  Event results such as `prompt.fill` and `command.run` return the result
  shape directly (`{ isFilled: true }`, `{}`).
- A `Text` element doesn't keep a `key`, so a test finds it by
  `{ type: 'Text', text }`. A JSX child like `Run /{x}?` is three string
  children; a template literal keeps it to one.
- After the first load the engine writes `tsconfig.json` and
  `.claude-plugin/types/` into the mod folder, so `tsc -p <mod>` works from
  then on. Before that, a scratch tsconfig that includes the skill's
  `types/claude-code.d.ts` does the same.
- Per the cats memory, `CATS_*` env vars were stripped from the
  `claude plugin validate` and `claude plugin test` runs.

## Verification

- `claude plugin validate`: passes. The only warning is that `plugin.json`
  has no author.
- `tsc -p <mod>`: clean.
- `claude plugin test`: 4 pass. The tests check that the shortcuts show on
  digits 1-3 (terminal and desktop), that /sess-wrap and /sess-load run bare,
  that /clear asks first and runs only on Yes (Cancel on `2`, Yes on `1`),
  and that Cancel runs nothing and restores the row.
- Hot reloading was enabled for the session, so each edit went live when the
  turn ended.

## Location

The mod was written in the per-session mods folder
(`~/.claude/dev-mods/<session-id>/skill-bar/`), which only this session
loads. After the wrap it was moved to a permanent folder:

- **Now at** `~/.claude/mods/skill-bar/`. The copy was checked identical with
  `diff -r` before the session copy was deleted. Validate, `tsc` and
  `claude plugin test` (4 pass) were re-run there.
- **Loaded in every session** by `CLAUDE_CODE_PLUGIN_DIRS` in the `env` block
  of `~/.claude/settings.json`:
  `"CLAUDE_CODE_PLUGIN_DIRS": "~/.claude/mods/skill-bar"`. This covers
  terminal and desktop sessions. More mods go in the same value, separated by
  `:`.
- **Hot reload:** interactive sessions watch that folder, so saving a file
  reloads the mod.
- **Takes effect** in sessions started after the change. The session that
  built it lost the band when its session copy was removed.
- **Sharing** would still mean publishing the folder as a marketplace repo and
  installing it with `/plugin install skill-bar --marketplace <owner>/<repo>`.

This is personal tooling, not dbc work, so it isn't on dbc's next-list.
