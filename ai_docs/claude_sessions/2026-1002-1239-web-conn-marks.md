# Web sidebar connection marks: no green dot for "added here", other tabs' connections shown

Session: `bafbc963-119d-455c-8a25-6a486fdd6ca2`

## Ask

From the cats-todo backlog: "Green dot still remains after a PG conn has be
disconnected". Then: "do we have anything to indicate what's connected and
what's not, or is only the focussed connection actually 'connected'?", and
of the three options offered, "For now can we do 2 by itself?"

## Diagnosis: the dot was never a connection mark

Both Disconnect paths clear the active mark properly:

- web: `handleDisconnect` sends `"conn" {active: ""}` and `markActive("")`
  drops `.active`
- TUI: `disconnectNow` makes `ws.Active()` return "", and the toolbar chip, the
  status bar and the Connections list's `●` are all drawn from it

The dot that stayed was `.conn-item[data-saved] .driver::before`: a `●` in
`--accent` (green, `#2e8f5f` by default) that means "added in the browser,
so editable and removable". It is provenance, so it never changes with
connection state. The user's PG connection had been added through the web
form, so it carried the dot. Configured and demo connections never do.

## Fix 1: the "added here" mark

`app.css`: the mark is now a muted `✎`, not a green dot. A green `●` is
what the TUI uses for the active connection, so in the web it read as
"connected". The CSS comment also said the connections are kept in
`web.bytdb`; they moved to `connections.toml`, and the comment now says so.
README updated.

## What "connected" actually means (the answer given)

The UIs mark only the connection of the tab on screen. More can be open:

- another web query tab's connection (in this window or another). Its pool
  is kept past this tab's Disconnect, which logs "N tabs still on X" only at
  that moment.
- a configured connection switched away from. The switch releases the session
  but keeps the `db.Manager` pool. Only derived `<conn>/<database>` pools are
  closed on a switch (`closeLeft`, `releaseThenClose`). The idle connection
  lingers until `conn_idle_timeout` (default 1h).
- an in-memory SQLite pool, which is never closed (closing it would destroy
  its contents).
- nothing checks liveness: a dropped server connection keeps its mark until a
  statement fails.

Options offered: (1) close a configured pool on switch-away when no tab
uses it, (2) mark the connections other tabs are on, (3) show actual pool
state. The recommendation was 1 + 2. The user chose 2 alone for now
(1 → Roadmap N-098).

## Fix 2: other tabs' connections (option 2)

```
connect / disconnect / tab closed / window forgotten
   └─► hub.announceInUse ─► per window: "inuse" {tabs: [{conn, ws?}, …]}
page boot / stream back after a drop ─► GET /api/v1/win/:id → inUse
page: markInUse ─► .conn-item.inuse (dimmed bar) + tooltip, leaving out state.ws
```

- `web/inuse.go` (new): `inUseTab`/`inUseEvent`, `tab.on()` (active, or the
  connection being dialed, as `tabsOn` counts it), `hub.inUseFor(w)`,
  `hub.announceInUse()`.
  - **Snapshots, not deltas**: tabs change connection from several
    goroutines, and a lost or reordered delta would leave a mark wrong. The
    list is a handful of entries.
  - **`hub.inUseMu`** wraps "read the tabs, then send", so racing
    announcements reach each stream in the order they read the state. It is
    taken before `hub.mu` and never after it.
  - **Tab IDs only for the receiving window's own tabs**: another window's
    tab is listed without its id.
  - **The page filters out its own tab**: which tab is on screen changes
    without a round trip.
- Hooks: `handleConnect` (after "connecting"), `deliver` on a non-stale
  `Connected`, `handleDisconnect`, `handleClose`, and `reap` when it forgets
  a window. `winState` carries `InUse`.
- `app.js`:
  - `markInUse` is called from `markActive`, `renderTabs` (tab switch,
    renames), the `inuse` and `conns` events, `resync`, and `src.onopen`,
    which fetches the snapshot.
  - The tooltip names this window's tabs by title. A derived connection
    names its database, e.g. "Query 2 (analytics)". Another window's tabs
    show as "a tab in another browser window".
  - The row's own tooltip is kept in `data-base-title`, so the in-use line
    does not stack on it.
- `app.css`: `.conn-item.inuse` is the active row's inset bar at 45% accent
  (`color-mix`). It sits before `.active`, so a row that is both shows the
  bright bar, and its tooltip still names the other tab.
- `conns.js`: a comment noting that the in-use mark is app.js's.
